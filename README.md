## 1. ชื่อโครงงานและสมาชิก

**ชื่อโครงงานภาษาไทย**
ระบบวางแผนเมนูและจัดซื้อผลผลิตชุมชนโดยใช้ AI

**ชื่อแอปพลิเคชัน**
เมนูชุมชน — Community Menu Planner

**แนวคิดของโครงงาน**
แอปพลิเคชันสำหรับร้านอาหารที่ช่วยวางแผนว่าแต่ละวันควรทำเมนูอะไร โดยนำวัตถุดิบที่มีในร้าน สูตรอาหาร และผลผลิตที่เกษตรกรในชุมชนพร้อมขายมาพิจารณาร่วมกัน

ผู้ใช้กำหนดงบซื้อวัตถุดิบเพิ่มและจำนวนจานที่ต้องการ จากนั้นระบบใช้ AI ช่วยเสนอเมนูจากสูตรที่ร้านบันทึกไว้ พร้อมอธิบายเหตุผล เมื่อผู้ใช้เลือกเมนู โปรแกรมจะคำนวณวัตถุดิบที่ต้องใช้ ปริมาณที่ต้องซื้อเพิ่ม และต้นทุนวัตถุดิบประมาณการ

**รูปแบบของโปรแกรม**
- เป็นแอปพลิเคชัน Desktop ติดตั้งและใช้งานบน Windows
- ออกแบบสำหรับร้านอาหารหนึ่งร้าน ใช้งานบนคอมพิวเตอร์หนึ่งเครื่อง
- มีฐานข้อมูลในเครื่องสำหรับเก็บข้อมูลร้าน
- ใช้อินเทอร์เน็ตเมื่อต้องเรียกบริการ AI
- งานคลัง สูตรอาหาร และจัดซื้อยังใช้งานได้เมื่อ AI ไม่พร้อมใช้งาน

## 2. ความเป็นมาของโครงงาน

ร้านอาหารต้องวางแผนเมนูและซื้อวัตถุดิบเป็นประจำ การตัดสินใจแต่ละครั้งเกี่ยวข้องกับข้อมูลหลายอย่าง เช่น ของที่เหลือในร้าน ปริมาณที่ต้องใช้ ราคาวัตถุดิบ และจำนวนอาหารที่คาดว่าจะขาย

หากข้อมูลเหล่านี้อยู่คนละที่ หรือใช้การจดจำเป็นหลัก อาจทำให้ตรวจสอบได้ยากว่าของชนิดใดมีอยู่แล้ว ของล็อตไหนควรใช้ก่อน และต้องซื้อเพิ่มจริง ๆ เท่าไร

### ปัญหาที่ต้องการศึกษา

1. **มองไม่เห็นวัตถุดิบคงเหลืออย่างชัดเจน**
   ร้านอาจต้องเดินตรวจของหรือเปิดสมุดหลายหน้า ก่อนจะทราบว่ามีวัตถุดิบเพียงพอสำหรับเมนูที่ต้องการหรือไม่
2. **ติดตามวัตถุดิบแต่ละล็อตได้ยาก**
   วัตถุดิบชนิดเดียวกันอาจรับเข้าหลายครั้ง แต่ละล็อตมีวันที่รับเข้าและวันที่ควรใช้ก่อนต่างกัน หากรวมยอดอย่างเดียวจะไม่ทราบว่าควรหยิบล็อตไหนมาใช้ก่อน
3. **คำนวณปริมาณซื้อเพิ่มใช้เวลา**
   เมื่อทำอาหารหลายเมนู วัตถุดิบบางรายการใช้ร่วมกัน ร้านต้องรวมความต้องการทั้งหมดก่อนหักของที่มีอยู่ จึงจะได้ปริมาณซื้อเพิ่มที่ถูกต้อง
4. **ข้อมูลผลผลิตชุมชนยังไม่เชื่อมกับการวางแผนเมนู**
   เกษตรกรอาจมีผลผลิตพร้อมขาย แต่ร้านยังไม่มีข้อมูลราคา ปริมาณ และวันที่พร้อมส่งอยู่ในระบบเดียวกับสูตรอาหาร

### แนวทางของโครงงาน

ระบบจะเชื่อมข้อมูลหลักสามส่วนเข้าด้วยกัน ได้แก่

| ข้อมูล | นำมาใช้ทำอะไร |
|---|---|
| วัตถุดิบในร้าน | ตรวจสอบของที่มี ปริมาณคงเหลือ และล็อตที่ควรใช้ก่อน |
| สูตรอาหาร | คำนวณว่าทำแต่ละเมนูต้องใช้วัตถุดิบเท่าไร |
| ผลผลิตชุมชน | ตรวจสอบแหล่งซื้อ ราคา ปริมาณ และวันพร้อมส่ง |

AI จะช่วยเสนอทางเลือกและอธิบายเหตุผล ส่วนปริมาณวัตถุดิบและต้นทุนจะคำนวณด้วยโปรแกรมจากข้อมูลที่บันทึกไว้

## 3. วัตถุประสงค์ของโครงงาน

**3.1 รวบรวมข้อมูลที่จำเป็นไว้ในระบบเดียว**
จัดเก็บข้อมูลวัตถุดิบ สูตรอาหาร เกษตรกร ผลผลิตพร้อมขาย และคำสั่งซื้อ เพื่อให้ค้นหาและนำข้อมูลมาใช้ร่วมกันได้สะดวก

**3.2 ช่วยวางแผนเมนูจากวัตถุดิบที่มี**
ช่วยให้ร้านพิจารณาเมนูที่ใช้วัตถุดิบในคลัง โดยแสดงล็อตที่ควรนำมาใช้ก่อนประกอบการตัดสินใจ

**3.3 ใช้ AI ช่วยเสนอเมนูและอธิบายเหตุผล**
เสนอเมนูจากสูตรที่ร้านบันทึกไว้ โดยพิจารณาเงื่อนไข เช่น งบซื้อเพิ่ม จำนวนจาน วัตถุดิบคงเหลือ และผลผลิตชุมชนที่พร้อมขาย

**3.4 คำนวณวัตถุดิบและรายการซื้อเพิ่ม**
คำนวณปริมาณที่ต้องใช้ตามจำนวนจาน รวมวัตถุดิบที่ใช้ร่วมกันหลายเมนู และเปรียบเทียบกับของในคลังเพื่อหาปริมาณที่ขาด

**3.5 แสดงต้นทุนวัตถุดิบประมาณการ**
แสดงยอดซื้อเพิ่มแยกจากต้นทุนวัตถุดิบทั้งหมด เพื่อให้ผู้ใช้เข้าใจว่าเงินที่ต้องจ่ายเพิ่มกับมูลค่าวัตถุดิบที่ใช้ทำอาหารเป็นคนละยอดกัน

**3.6 สรุปข้อมูลเพื่อใช้ทบทวนการทำงาน**
แสดงรายงานการจัดซื้อ การเบิกใช้ ของเสีย และยอดซื้อจากเกษตรกรในชุมชนตามช่วงเวลาที่เลือก

## 4. ขีดความสามารถและตัวอย่างการทำงาน

### 4.1 ผู้ใช้งานและขอบเขต

ผู้ใช้งานหลักคือเจ้าของร้านหรือพนักงานที่ได้รับมอบหมาย โดยใช้งานบนคอมพิวเตอร์ของร้านหนึ่งเครื่อง

เกษตรกรส่งข้อมูลผ่านช่องทางเดิม เช่น โทรศัพท์หรือข้อความ แล้วพนักงานนำข้อมูลมาบันทึกในโปรแกรม เกษตรกรไม่ต้องติดตั้งแอปพลิเคชันในขอบเขตระยะแรก

### 4.2 หน้าหลัก

หน้าหลักสรุปข้อมูลที่ควรตรวจสอบก่อนเริ่มวางแผน ได้แก่
- วัตถุดิบที่เหลือต่ำกว่าระดับขั้นต่ำ
- ล็อตวัตถุดิบที่ใกล้วันที่ควรใช้ก่อน
- คำสั่งซื้อที่ยังรอรับสินค้า
- แผนเมนูของวันที่เลือก

ผู้ใช้สามารถกดจากรายการสรุปเพื่อเปิดรายละเอียดของแต่ละส่วนได้

### 4.3 คลังวัตถุดิบ

รองรับการเพิ่ม แก้ไข และค้นหาข้อมูลวัตถุดิบ รวมถึงบันทึกการรับเข้า เบิกใช้ ของเสีย และปรับยอดพร้อมเหตุผล

การเก็บข้อมูลจะแยกตามล็อต เช่น

| วัตถุดิบ | ล็อต | คงเหลือ | แนวทางการใช้ |
|---|---|---|---|
| ฟักทอง | ล็อต A | 2 กิโลกรัม | เสนอให้ใช้ก่อน หากสภาพจริงยังเหมาะสม |
| ฟักทอง | ล็อต B | 5 กิโลกรัม | ใช้ต่อจากล็อต A ตามความต้องการ |

ระบบต้องเก็บประวัติว่าปริมาณเปลี่ยนจากรายการใด ไม่เปิดให้เปลี่ยนยอดคงเหลือโดยไม่มีหลักฐานอ้างอิง

วันที่ที่บันทึกไว้ใช้ช่วยเตือนและจัดลำดับล็อต ผู้ใช้ยังต้องตรวจสอบสภาพวัตถุดิบจริงก่อนใช้

### 4.4 สูตรอาหาร

ผู้ใช้บันทึกชื่อเมนูและปริมาณวัตถุดิบต่อหนึ่งจาน เมื่อระบุจำนวนจาน ระบบจะคำนวณปริมาณรวมให้อัตโนมัติ

ตัวอย่างสูตรส่วนหนึ่งของเมนูฟักทองผัดไข่:

| วัตถุดิบ | ปริมาณต่อจาน |
|---|---|
| ฟักทอง | 100 กรัม |
| ไข่ | 1 ฟอง |

สูตรที่ใช้จริงต้องบันทึกน้ำมันและเครื่องปรุงด้วย เพื่อให้คำนวณต้นทุนวัตถุดิบได้ครบตามสูตร

ระบบกำหนดหน่วยมาตรฐานของวัตถุดิบแต่ละชนิด เช่น กรัม มิลลิลิตร หรือฟอง และแปลงเฉพาะหน่วยที่เทียบกันได้ เช่น 1 กิโลกรัมเท่ากับ 1,000 กรัม

### 4.5 ข้อมูลเกษตรกรและผลผลิตชุมชน

จัดเก็บข้อมูลผู้ขายและรายการผลผลิต ได้แก่
- ชื่อเกษตรกรหรือกลุ่มผู้ผลิต
- พื้นที่และข้อมูลติดต่อ
- วัตถุดิบที่พร้อมขาย
- ราคาต่อหน่วยและปริมาณพร้อมขาย
- วันที่พร้อมส่ง
- วันที่อัปเดตข้อมูลล่าสุด

ก่อนยืนยันคำสั่งซื้อ พนักงานต้องตรวจสอบราคาและปริมาณกับผู้ขาย เพราะข้อมูลที่บันทึกไว้อาจเปลี่ยนแปลงได้

### 4.6 การแนะนำเมนูด้วย AI

ผู้ใช้ระบุวันที่ต้องการวางแผน งบซื้อเพิ่ม จำนวนจาน และเมนูที่ไม่ต้องการ จากนั้นระบบส่งข้อมูลที่จำเป็นให้ AI เพื่อเสนอเมนูประมาณ 3 ทางเลือก

ตัวอย่างเหตุผลประกอบ:


AI เลือกได้เฉพาะเมนูที่มีรหัสอยู่ในฐานข้อมูล หลังรับคำตอบ โปรแกรมจะตรวจสอบรหัสเมนูและคำนวณปริมาณกับต้นทุนใหม่ก่อนแสดงผล

หากงบไม่พอ วัตถุดิบไม่เพียงพอ หรือวันส่งไม่ทัน ระบบต้องแสดงข้อจำกัดให้ผู้ใช้เห็น ไม่แสดงว่าแผนนั้นทำได้โดยไม่มีเงื่อนไข

AI ทำหน้าที่ช่วยแนะนำ ผู้ใช้เป็นผู้เลือกและยืนยัน การขอคำแนะนำจะไม่สร้างคำสั่งซื้อหรือหักยอดคลังอัตโนมัติ

### 4.7 การจัดซื้อและรับสินค้า

เมื่อเลือกแผนเมนูแล้ว ผู้ใช้สามารถนำรายการวัตถุดิบที่ขาดไปสร้างคำสั่งซื้อ โดยเลือกผู้ขาย จำนวน ราคา และวันนัดรับ

การสร้างคำสั่งซื้อยังไม่เพิ่มยอดคลัง ยอดคลังจะเพิ่มเมื่อผู้ใช้บันทึกรับสินค้าจริง โดยรับเข้าเป็นล็อตพร้อมข้อมูลวันที่และต้นทุน

หากซื้อจากหลายราย ระบบแยกคำสั่งซื้อตามผู้ขาย และต้องป้องกันการบันทึกรับสินค้ารายการเดิมซ้ำ

### 4.8 รายงาน

ระบบแสดงรายงานตามช่วงเวลาที่เลือก ได้แก่
- ยอดจัดซื้อวัตถุดิบ
- การเบิกใช้วัตถุดิบ
- ปริมาณของเสียและเหตุผล
- ยอดจัดซื้อแยกตามเกษตรกร
- มูลค่าการซื้อผลผลิตจากชุมชน

รายงานสะท้อนข้อมูลที่ผู้ใช้บันทึก หากไม่ได้บันทึกการเบิกหรือของเสียครบ ยอดรายงานย่อมไม่ตรงกับการทำงานจริง

80 บาทเป็นยอดซื้อเพิ่มของสองรายการนี้ ต้นทุนเมนูต้องรวมมูลค่าฟักทองและไข่ที่เบิกจากคลัง รวมทั้งน้ำมันและเครื่องปรุงตามสูตรด้วย

**ลำดับการสาธิต**
1. เปิดคลังให้เห็นฟักทองคงเหลือและข้อมูลล็อต
2. เปิดข้อมูลผู้ขายที่มีฟักทองพร้อมส่ง
3. กำหนดงบซื้อเพิ่มและให้ AI เสนอเมนู
4. เลือกฟักทองผัดไข่ 30 จาน แล้วแสดงรายการซื้อเพิ่ม
5. สร้างคำสั่งซื้อและบันทึกรับสินค้า
6. แสดงยอดคลังหลังรับสินค้า
7. ยืนยันเบิกวัตถุดิบตามแผน แล้วเปิดรายงานที่เกี่ยวข้อง

## 5. โมเดลพัฒนาซอฟต์แวร์

โครงงานนี้เสนอใช้ **Incremental Model** หรือโมเดลการพัฒนาแบบเพิ่มส่วนงาน โดยแบ่งการพัฒนาออกเป็นรอบ เริ่มจากส่วนพื้นฐานที่จำเป็นก่อน เมื่อส่วนแรกใช้งานและทดสอบได้แล้ว จึงเพิ่มความสามารถส่วนถัดไปจนระบบครบตามขอบเขต เหมาะกับการพัฒนาคนเดียว เพราะช่วยแบ่งงานให้ชัดเจนและตรวจสอบปัญหาได้ทีละส่วน

แต่ละรอบมีขั้นตอนดังนี้
1. **วิเคราะห์ความต้องการ** — กำหนดว่าส่วนนั้นต้องทำอะไร รับข้อมูลอะไร และแสดงผลแบบไหน
2. **ออกแบบ** — วางหน้าจอ โครงสร้างข้อมูล และลำดับการทำงาน
3. **พัฒนาโปรแกรม** — เขียนโค้ดและเชื่อมต่อฐานข้อมูล
4. **ทดสอบและปรับปรุง** — ตรวจความถูกต้อง แก้ปัญหา และทดสอบการเชื่อมกับส่วนที่ทำไว้ก่อนหน้า

สำหรับแอปพลิเคชัน "เมนูชุมชน" แบ่งการพัฒนาเป็น 4 รอบ

| รอบพัฒนา | ส่วนที่พัฒนา | ผลที่ควรได้ |
|---|---|---|
| รอบที่ 1: ข้อมูลพื้นฐาน | ฐานข้อมูล คลังวัตถุดิบ การรับเข้าและเบิกตามล็อต รวมถึงสูตรอาหาร | บันทึกวัตถุดิบ ตรวจยอดคงเหลือ และจัดเก็บสูตรอาหารได้ |
| รอบที่ 2: ข้อมูลชุมชนและจัดซื้อ | ข้อมูลเกษตรกร ผลผลิตพร้อมขาย คำสั่งซื้อ และการรับสินค้า | เลือกผู้ขาย สร้างคำสั่งซื้อ และรับสินค้าเข้าคลังได้ |
| รอบที่ 3: วางแผนเมนูและ AI | กำหนดจำนวนจาน คำนวณวัตถุดิบ ซื้อเพิ่มและต้นทุน พร้อมเชื่อม AI แนะนำเมนู | เลือกเมนูและเห็นปริมาณที่ต้องใช้ ยอดซื้อเพิ่ม และข้อจำกัดของแผนได้ |
| รอบที่ 4: รายงานและทดสอบรวม | รายงานการจัดซื้อ การเบิกใช้ ของเสีย และยอดซื้อจากชุมชน | ดูรายงานและทดสอบการทำงานต่อเนื่องตั้งแต่วางแผนจนถึงเบิกวัตถุดิบได้ |

**เหตุผลที่เลือกใช้โมเดลนี้**
- แบ่งงานขนาดใหญ่ให้เป็นส่วนที่ผู้พัฒนาคนเดียวจัดการได้
- มีส่วนของโปรแกรมให้ทดลองใช้งานเมื่อจบแต่ละรอบ
- ตรวจพบและแก้ไขปัญหาได้ก่อนเพิ่มส่วนถัดไป
- ปรับรายละเอียดจากผลการทดสอบได้ในแต่ละรอบ
- ทดสอบฐานข้อมูลและการคำนวณให้ถูกต้องก่อนนำ AI มาเชื่อมต่อ

## 6. โครงสร้างของโครงงานในภาพรวม

ระบบแบ่งออกเป็น 4 ส่วนหลัก

### 6.1 หน้าจอ Desktop

เป็นส่วนที่ผู้ใช้เห็นและกดใช้งาน เช่น หน้าคลัง สูตรอาหาร แผนเมนู และคำสั่งซื้อ
หน้าที่หลักคือรับข้อมูล แสดงรายละเอียด แจ้งข้อผิดพลาด และให้ผู้ใช้ตรวจสอบก่อนยืนยันรายการสำคัญ

### 6.2 ส่วนประมวลผล

เป็นส่วนที่จัดการกติกาการทำงาน เช่น
- ตรวจสอบว่าจำนวนและราคาที่กรอกถูกต้อง
- คูณสูตรตามจำนวนจาน
- รวมวัตถุดิบที่ใช้ร่วมกันหลายเมนู
- หาปริมาณที่ต้องซื้อเพิ่ม
- คำนวณต้นทุน
- เลือกล็อตสำหรับเบิกและป้องกันยอดติดลบ
- ตรวจสถานะก่อนรับสินค้าหรือเบิกของ

### 6.3 ฐานข้อมูลในเครื่อง

เก็บข้อมูลของร้านอย่างเป็นระบบ เพื่อเรียกดู แก้ไข และตรวจสอบประวัติย้อนหลัง

| กลุ่มข้อมูล | รายละเอียดสำคัญ |
|---|---|
| วัตถุดิบ | รหัส ชื่อ หน่วยมาตรฐาน ระดับขั้นต่ำ |
| ล็อตวัตถุดิบ | วัตถุดิบ วันที่รับเข้า วันที่ควรใช้ก่อน ปริมาณ ต้นทุนต่อหน่วย |
| ประวัติเคลื่อนไหว | ประเภทการเคลื่อนไหว จำนวน วันเวลา เหตุผล และรายการอ้างอิง |
| เมนูและสูตร | ชื่อเมนู วัตถุดิบ และปริมาณต่อจาน |
| เกษตรกร | ชื่อ พื้นที่ และข้อมูลติดต่อ |
| ผลผลิตพร้อมขาย | ผู้ขาย วัตถุดิบ ราคา ปริมาณ และวันพร้อมส่ง |
| แผนเมนู | วันที่ งบ สถานะ เมนูที่เลือก และจำนวนจาน |
| คำสั่งซื้อ | ผู้ขาย วันที่ สถานะ และรายการวัตถุดิบที่สั่ง |

**ความสัมพันธ์ที่อธิบายให้อาจารย์เข้าใจได้ง่าย**
- วัตถุดิบหนึ่งชนิดมีได้หลายล็อต
- เมนูหนึ่งเมนูใช้วัตถุดิบหลายชนิด
- วัตถุดิบหนึ่งชนิดอยู่ในได้หลายสูตร
- เกษตรกรหนึ่งรายเสนอขายผลผลิตได้หลายรายการ
- แผนหนึ่งแผนเลือกได้หลายเมนู
- คำสั่งซื้อหนึ่งใบมีรายการซื้อหลายรายการ

ควรกำหนดวิธีสำรองและกู้คืนฐานข้อมูลด้วย เพราะข้อมูลหลักเก็บอยู่ในคอมพิวเตอร์ของร้าน

### 6.4 ส่วนเชื่อมต่อ AI

รับข้อมูลที่จำเป็นจากระบบ จัดเตรียมคำขอ ส่งไปยังบริการ AI และตรวจคำตอบที่ได้รับ

ข้อมูลติดต่อของเกษตรกรไม่จำเป็นต่อการแนะนำเมนู จึงไม่ควรส่งไปพร้อมคำขอ AI ส่วนรหัสสำหรับเรียกบริการ AI ต้องแยกจากโค้ดที่เผยแพร่บน GitHub

หาก AI ใช้งานไม่ได้ ระบบให้ผู้ใช้เลือกเมนูเอง แล้วใช้ส่วนคำนวณเดิมต่อได้

## 7. อธิบายโค้ดในแต่ละส่วนโดยสรุป

หัวข้อนี้ควรเปิดโค้ดจริงเฉพาะจุดสำคัญ แล้วอธิบายว่า **"รับข้อมูลอะไร ประมวลผลอย่างไร และได้ผลอะไร"** ไม่จำเป็นต้องอ่านโค้ดทุกบรรทัด

### 7.1 ส่วนจัดการข้อมูล

ทำหน้าที่รับข้อมูลจากหน้าจอ ตรวจความครบถ้วน แล้วบันทึกลงฐานข้อมูล เช่น ชื่อวัตถุดิบต้องไม่ว่าง และปริมาณรับเข้าต้องมากกว่าศูนย์

เมื่อผู้ใช้ค้นหา โปรแกรมจะอ่านข้อมูลที่ตรงเงื่อนไขกลับมาแสดงบนหน้าจอ

### 7.2 ส่วนคลังวัตถุดิบ

เมื่อรับสินค้า โปรแกรมสร้างล็อตและบันทึกรายการรับเข้า

เมื่อเบิกใช้ โปรแกรมตรวจยอดที่ใช้ได้ เสนอล็อตตามวันที่ควรใช้ก่อน และบันทึกว่าหักจากล็อตใดเท่าไร หากยอดไม่พอจะต้องหยุดและแจ้งผู้ใช้

การเปลี่ยนยอดกับการบันทึกประวัติต้องสำเร็จพร้อมกัน เพื่อป้องกันยอดเปลี่ยนแต่ไม่มีรายการอ้างอิง

### 7.3 ส่วนคำนวณแผนเมนู

ใช้สูตรหลัก:

```
ปริมาณที่ต้องใช้ = ปริมาณต่อจาน × จำนวนจาน
```

ตัวอย่าง ฟักทองจานละ 100 กรัม จำนวน 30 จาน: `100 × 30 = 3,000 กรัม`

หากเลือกหลายเมนู ต้องรวมความต้องการของวัตถุดิบชนิดเดียวกันก่อนหักคลัง เช่น เมนูแรกใช้ฟักทอง 3 กิโลกรัม และเมนูที่สองใช้ 1 กิโลกรัม ความต้องการรวมคือ 4 กิโลกรัม

### 7.4 ส่วนคำนวณซื้อเพิ่ม

ใช้สูตร:

```
ปริมาณซื้อเพิ่ม = ค่าสูงสุดระหว่าง 0 กับ (ปริมาณที่ต้องใช้ − ปริมาณคงเหลือที่ใช้ได้)
```

ถ้าต้องใช้ฟักทอง 3 กิโลกรัม และมีที่ใช้ได้ 2 กิโลกรัม จะต้องซื้อเพิ่ม 1 กิโลกรัม
ถ้ามีมากกว่าที่ต้องใช้ ปริมาณซื้อเพิ่มจะเป็นศูนย์

### 7.5 ส่วนคำนวณต้นทุน

แยกแสดงสองยอด:

| ยอดที่แสดง | วิธีคิด |
|---|---|
| งบซื้อเพิ่ม | ปริมาณที่ต้องซื้อ × ราคาซื้อที่เลือก |
| ต้นทุนวัตถุดิบประมาณการ | มูลค่าวัตถุดิบจากคลังที่ใช้ + มูลค่าวัตถุดิบที่ซื้อเพิ่มแล้วนำมาใช้ |

ต้นทุนจากคลังคิดตามล็อตที่เสนอให้เบิก หากเบิกหลายล็อตที่มีราคาต่างกัน ต้องรวมต้นทุนตามปริมาณของแต่ละล็อต

ยอดนี้เป็นต้นทุนวัตถุดิบตามสูตร ยังไม่ใช่ต้นทุนธุรกิจทั้งหมด หากไม่ได้รวมค่าแรง ค่าไฟ ค่าเช่า หรือค่าใช้จ่ายอื่นไว้ในขอบเขต

### 7.6 ส่วนเชื่อมต่อ AI

โค้ดส่วนนี้ทำหน้าที่:
1. อ่านสูตรและข้อมูลวัตถุดิบที่เกี่ยวข้อง
2. แนบเงื่อนไขของผู้ใช้
3. ส่งคำขอให้ AI เลือกรหัสเมนูพร้อมเหตุผล
4. ตรวจรูปแบบคำตอบและรหัสเมนู
5. ส่งเมนูที่ผ่านการตรวจให้โปรแกรมคำนวณตัวเลข
6. แสดงคำแนะนำพร้อมข้อจำกัด

หากคำตอบไม่ถูกต้องหรือบริการไม่ตอบกลับ ต้องแจ้งผู้ใช้และให้เลือกเมนูเองได้

### 7.7 ส่วนจัดซื้อและรายงาน

ส่วนจัดซื้อตรวจสถานะคำสั่งซื้อก่อนบันทึกรับสินค้า เพื่อป้องกันรับรายการเดิมซ้ำ

ส่วนรายงานอ่านรายการที่เกิดขึ้นจริง เช่น การรับสินค้า การเบิกใช้ และการบันทึกของเสีย แล้วรวมยอดตามช่วงเวลาหรือผู้ขายที่เลือก

## 8. ปัญหาและแนวทางแก้ไข


| ปัญหาที่คาดว่าจะพบ | ผลกระทบ | แนวทางแก้ไข |

| AI ให้ตัวเลขไม่ตรงข้อมูล | รายการซื้อและต้นทุนผิด | ให้โปรแกรมคำนวณตัวเลขเอง |
| ใช้หน่วยกิโลกรัมปนกับกรัม | ปริมาณคลาดเคลื่อน | แปลงเป็นหน่วยมาตรฐานก่อนคำนวณ |

| ราคาและปริมาณผลผลิตเปลี่ยน | คำสั่งซื้อไม่ตรงของจริง | แสดงวันอัปเดตและยืนยันกับผู้ขาย |

| เบิกเกินยอดที่ใช้ได้ | ไม่ยืนยันรายการและยอดไม่ติดลบ |
| รับคำสั่งซื้อเดิมซ้ำ | ไม่เพิ่มยอดคลังซ้ำ |
| AI ส่งรหัสเมนูที่ไม่มี | ไม่ให้เลือกเมนูดังกล่าว |
| AI ใช้งานไม่ได้ | เลือกเมนูเองและคำนวณต่อได้ |

## 9. การนำไปประยุกต์ใช้งาน

### 9.1 ลักษณะร้านที่เหมาะกับการทดลอง

เริ่มจากร้านอาหารหนึ่งร้านที่มีเมนูประจำ มีสูตรที่สามารถระบุปริมาณได้ และมีการซื้อวัตถุดิบจากผู้ขายในพื้นที่

ควรมีผู้รับผิดชอบอัปเดตคลังอย่างชัดเจน เพราะคุณภาพของคำแนะนำและการคำนวณขึ้นอยู่กับข้อมูลที่บันทึก

### 9.2 ขั้นตอนใช้งานในร้าน

| ช่วงเวลา | สิ่งที่ทำ |
|---|---|
| ก่อนเริ่มใช้งาน | บันทึกวัตถุดิบ สูตรอาหาร ผู้ขาย และยอดคลังเริ่มต้น พร้อมตรวจสอบหน่วยและต้นทุนให้ตรงกัน |
| ก่อนวางแผนประจำวัน | ตรวจสภาพวัตถุดิบ บันทึกของเสีย และอัปเดตข้อมูลผลผลิตที่พร้อมขาย |
| ช่วงวางแผนเมนู | กำหนดงบและจำนวนจาน ขอคำแนะนำจาก AI หรือเลือกเมนูเอง แล้วตรวจรายการซื้อเพิ่ม |
| ช่วงจัดซื้อและรับสินค้า | ยืนยันข้อมูลกับผู้ขาย สร้างคำสั่งซื้อ และรับสินค้าเข้าคลังตามปริมาณจริง |
| ช่วงเตรียมอาหารและหลังใช้งาน | ยืนยันเบิกวัตถุดิบ บันทึกของเสียที่เกิดขึ้น และตรวจรายงานเพื่อใช้วางแผนครั้งถัดไป |

### 9.3 ประโยชน์ที่คาดว่าจะได้รับ

**ด้านร้านอาหาร**
- เห็นวัตถุดิบคงเหลือและล็อตที่ควรใช้ก่อน
- ทราบว่าต้องซื้อเพิ่มเท่าไรก่อนสั่ง
- เปรียบเทียบแผนกับงบซื้อเพิ่มได้
- ตรวจสอบประวัติรับเข้า เบิกใช้ และของเสียย้อนหลังได้

**ด้านเกษตรกรและชุมชน**
- ร้านมีข้อมูลผลผลิตพร้อมขายสำหรับใช้ประกอบการเลือกเมนู
- รายการสั่งซื้อระบุวัตถุดิบ จำนวน และกำหนดรับได้ชัดเจน
- มีข้อมูลสรุปมูลค่าการจัดซื้อจากผู้ขายในชุมชน

**ด้านผู้พัฒนา**
- ได้ฝึกออกแบบแอปพลิเคชัน Desktop และฐานข้อมูล
- ได้ฝึกการคำนวณจากข้อมูลหลายส่วน
- ได้เรียนรู้การเชื่อม AI และตรวจสอบผลลัพธ์ก่อนใช้งาน
- ได้ฝึกพัฒนา ทดสอบ และทำงานร่วมกันผ่าน GitHub

### 9.4 วิธีประเมินหลังทดลองใช้งาน

ควรเปรียบเทียบข้อมูลในช่วงก่อนและหลังทดลองที่มีลักษณะการทำงานใกล้เคียงกัน โดยพิจารณา:

- จำนวนรายการซื้อซ้ำที่ตรวจพบ
- ปริมาณของเสียที่บันทึก
- ความถูกต้องของยอดคลังเมื่อเทียบกับการตรวจนับ
- มูลค่าการซื้อวัตถุดิบจากชุมชน
- ความคิดเห็นของผู้ใช้เกี่ยวกับความสะดวกและความเข้าใจหน้าจอ

## วิธีเปิดใช้

### แบบง่ายสุด: ใช้ไฟล์ .exe
ดับเบิลคลิก `CommunityMenu.exe` ได้เลย ไม่ต้องติดตั้งอะไร

- ควรวางไฟล์ไว้ในโฟลเดอร์ของมันเอง เช่น `เอกสาร\CommunityMenu\`
  เพราะโปรแกรมจะสร้างไฟล์เก็บข้อมูล `community_menu.db` ไว้ข้าง ๆ
- ถ้า Windows เตือน "Windows protected your PC" ให้กด **More info → Run anyway**
  (เตือนเพราะไฟล์ไม่ได้ซื้อใบรับรองจาก Microsoft ไม่ใช่ไวรัส)
- **สำรองข้อมูล** = ก๊อปไฟล์ `community_menu.db` เก็บไว้
- **เริ่มใหม่ด้วยข้อมูลสมมติ** = ปิดโปรแกรม ลบไฟล์ `community_menu.db` แล้วเปิดใหม่

### แบบรันจากโค้ด (สำหรับคนที่จะแก้โปรแกรม)
1. ติดตั้ง Python 3.10 ขึ้นไป จาก https://www.python.org
   (ตอนติดตั้งให้ติ๊กช่อง **Add python.exe to PATH**)
2. เปิด Command Prompt ในโฟลเดอร์นี้ แล้วพิมพ์
   ```
   pip install -r requirements.txt
   ```
3. เปิดโปรแกรม
   ```
   python main.py
   ```

คำสั่งอื่นที่มีประโยชน์:
```
python db.py            ล้างข้อมูลทั้งหมด แล้วใส่ข้อมูลสมมติใหม่ (ใช้ก่อนนำเสนอ)
python -m unittest -v   ตรวจว่าโปรแกรมยังคิดเลขถูก (ขึ้น OK = ผ่าน)
```

## ลองใช้ตามลำดับนี้ (ตัวอย่าง: ฟักทองผัดไข่ 30 จาน)

1. **คลังวัตถุดิบ** → คลิกฟักทอง จะเห็นว่ามี 2 กก. และใกล้ถึงวันควรใช้ก่อน
2. **ข้อมูลชุมชน** → เห็นเกษตรกรขายฟักทอง 30 บาท/กก. ไข่ 5 บาท/ฟอง
3. **แผนเมนูและ AI** → ใส่งบ 100 บาท, 30 จาน → กด **ให้ AI แนะนำเมนู**
4. เลือกฟักทองผัดไข่ 30 จาน → โปรแกรมบอกว่าต้องซื้อฟักทอง 1 กก. + ไข่ 10 ฟอง **รวม 80 บาท**
5. กด **ยืนยันแผน + สร้างคำสั่งซื้อ** → ไปแท็บ **การจัดซื้อ** → กด **บันทึกรับสินค้า** → ของในคลังเพิ่มขึ้น
6. กลับแท็บแผนเมนู → กด **ยืนยันเบิกวัตถุดิบตามแผน** → เปิดแท็บ **รายงาน** ดูสรุป
